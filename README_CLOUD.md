# 期货分析工作台 —— 云端常驻部署指南（脱离本机）

本目录已改造为**完全可移植**的流水线：所有脚本均按自身位置解析路径，不再依赖本机固定盘符；
`web/` 是一个**零第三方依赖**（纯 Python 标准库 `http.server`）的网站，可在任意装有 Python3 的机器上直接运行。

## 一、两套落地方案

| 方案 | 适用 | 是否需要本机开机 | 访问方式 |
|---|---|---|---|
| **A. WorkBuddy 云端自动化**（已内置） | 不想折腾服务器 | 否（云端沙箱执行，需 WorkBuddy 客户端在线触发） | wbapp 分享链接 |

> 说明：此前实测，**云端沙箱具备独立运行能力**——Python、akshare、外网、项目副本齐全，并能成功部署到 wbapp。
> 唯一前提是触发派发需要 WorkBuddy 客户端在线。若要做到"关机也自动更新"，请用**方案 B** 把流水线搬到常驻云服务器。

## 二、方案 B：部署到任意云服务器 / 容器

### 方式 1：Docker（推荐，最省心）

```bash
# 1) 把整个项目目录上传到服务器（或 git clone）
# 2) 构建镜像
docker build -t futures-workbench .

# 3) 运行（把 data/ 挂成持久卷，刷新数据跨重启保留）
docker run -d --name fw \
  -p 8011:8011 \
  -v fw-data:/opt/futures-workbench/data \
  futures-workbench

# 4) 浏览器访问 http://<服务器公网IP>:8011
```

容器启动后会：首次自动构建 `web/` → 启动常驻网站 → 启用 cron（按 crontab 定时刷新）。

> 安全建议：生产环境请用 Nginx/Caddy 反代 8011 并加 HTTPS + 访问鉴权，不要直接暴露裸端口。

### 方式 2：裸机 / 轻量应用服务器（无 Docker）

```bash
# 依赖
pip install akshare        # 仅前20净持仓/标准仓单需要；可省略（届时这两项跳过）

# 安装 cron 并写入计划
crontab crontab            # 计划内容见 crontab 文件（19:30数据/08:30观点/12:30+18:30补跑）

# 常驻运行 web 服务（用 nohup / systemd / supervisor 任选）
HOST=0.0.0.0 PORT=8011 nohup python web/app/main.py > web.log 2>&1 &
```

### 方式 3：云函数（腾讯云 SCF / 阿里云 FC 定时触发器）

云函数适合"事件触发"而非"常驻网站"。两种用法：
- **只做刷新+发布**：用平台的**定时触发器**调用 `python cloud_cron.py both`，把 `web/` 发布到对象存储 / 或推回 wbapp（设 `WBAPP_DEPLOY_CMD`）。
- **要常驻访问**：仍需一个常驻主机（方案 1/2）来 serve `web/`。云函数不适合长期 hold 住 HTTP 服务。

## 三、定时时间表（与工作台一致）

| 时间 | 星期 | 任务 | 命令 |
|---|---|---|---|
| 19:30 | 周一~周五 | 交易所直抓数据刷新主跑（K线/标准仓单/前20净持仓等收盘数据） | `python cloud_cron.py data` |
| 08:30 | 每天 | 市场情绪/机构观点自动抓取（qhkch直抓+WebSearch合并+重建） | `python cloud_cron.py opinion` |

> 注：原 12:30 / 18:30「补跑 both」两个冗余任务在 WorkBuddy 云端自动化中已取消（PAUSED）。
> 在方案 B 自托管环境里，cron 不依赖客户端，补跑零成本，已在 `crontab` 中保留为**可选注释行**，建议按需取消注释作为兜底。
>
> ⚠️ **方案 B 关键限制（若改日采用方案 B 才需关注）**：08:30 的「WebSearch 全网」观点部分依赖 **AI 代理（LLM）** 才能完成——
> 它需要先由 Agent 检索各品种机构研报并落盘补丁 `collect/_websearch_opinions.json`，`opinion` 模式才合并。
> **纯服务器 cron 环境没有 LLM，因此 WebSearch 全网部分不会自动更新**（脚本会自动跳过，沿用上一次补丁）。
> 也就是说，方案 B 下：
> - **K线 / 标准仓单 / 前20净持仓**：每日 19:30 全自动、最新鲜 ✅
> - **qhkch 机构观点**：每日 08:30 全自动直抓、最新鲜 ✅
> - **WebSearch 全网观点**：冻结为最后一次由 Agent 写入的补丁（需你偶尔跑一次云端 08:30 任务才会刷新）
>
> 若希望 WebSearch 也全自动，可保留 WorkBuddy 云端 08:30 观点任务作为"补丁来源"，并额外做一步把补丁同步到服务器（scp / 对象存储 / IMA 知识库），属进阶集成，需要时再议。

## 五、运维 & 排错

- **运行报告**：每次 `cloud_cron.py` 跑完写 `run_report.json`（含各步状态、耗时、Python 版本）。
- **刷新状态**：`collect/refresh_status.json`（refresh_daily 内部产出）。
- **数据不更新**：检查容器/服务器是否可访问外网（新浪行情 `stock2.finance.sina.com.cn`、奇货可查 `x.qhkch.com`、akshare 后端）。
- **前20/仓单为空**：交易所当日数据未公布（盘后延迟）时抓取会失败，属预期；保留上次好数据，次日自动补齐。
- **缠论不可用**：未挂载缠论引擎（`WB_CHANLUN_PATH`）时自动降级，K线/均线/观点不受影响。
- **改用 wbapp 托管**：设环境变量 `WBAPP_DEPLOY_CMD` 为你的发布命令，`deploy` 模式会自动调用；否则自托管。

## 六、手机端使用云工作区（日常操作）

本工作台已经是云工作区：对话跨设备同步、定时任务在云端沙箱执行、网页部署在 wbapp。
电脑关机后，手机照常可用，只需走对入口。

### 1. 只看最新数据（最简单，无需 WorkBuddy）

手机浏览器直接打开：

```
https://futures-workbench-01415.app.workbuddy.host/?sharecode=24XEIRXDFJ
```

右上角「数据日期」显示最近一次刷新状态（含 K线41 / 仓单✓ / 情绪✓）。关电脑也能看。

### 2. 手动触发 / 补跑刷新任务

- **方式 A（自动化列表）**：WorkBuddy App → 侧边栏「自动化 / 任务」→ 找到
  - `期货工作台云端·数据刷新主跑(工作日19:30)`
  - `期货工作台每日市场情绪自动抓取(08:30)`
  → 点「运行」即可立即执行。
- **方式 B（现有对话）**：打开**这个「期货分析工作台」对话**（不要新建！）→ 发任意消息。
  活跃会话会触发错过的定时任务自动补跑（实测：电脑关机后，手机在对话里发消息即触发 20:56 那次数据刷新）。

### ⚠️ 常见误区：手机提示「找不到任务」

在手机上点「**新建对话**」会得到**一个空白、不带本工作区上下文**的新会话，
而两个定时任务绑定在「期货分析工作台」工作区里，空白对话不在此工作区，故报"找不到任务"。
**任务没丢，是入口错了**——请改用上面的「自动化列表」或「现有对话」，不要新建对话。

### 3. 为什么有时"到点没自动跑"

云端定时任务派发条件 = **到点 + 存在本工作区的活跃会话**。
若到点时你既没开电脑也没在手机上进入本工作区对话，任务会挂起，
直到你下次在手机/桌面进本工作区对话并发消息时才补发（可能延后，但不会丢）。

> 想彻底"关机也按时自动跑"，见「方案 B 自托管云服务器」（需你自备常驻服务器）。
